# go-sumtype

Zero-dependency code generator for Go sum types (tagged unions). Eliminates the boilerplate of writing sealed-interface method stubs for every variant, while keeping the type definitions you write valid, idiomatic Go.

Works with [go-check-sumtype](https://github.com/alecthomas/go-check-sumtype) to enforce exhaustive type switches at lint time.

## Why a generator?

The marker methods themselves are trivial — `func (*Circle) isShape() {}` takes seconds to write. The problem is that they live alongside your type definitions and distract from what actually matters: the shape of your data.

When you open a file to understand your domain types, you want to see:

```go
type Shape interface{ isShape() }

type (
    Circle   struct{ Radius float64 }
    Square   struct{ Side float64 }
    Triangle struct{ Base, Height float64 }
)
```

Not this:

```go
type Shape interface{ isShape() }

type Circle struct{ Radius float64 }
func (*Circle) isShape() {}

type Square struct{ Side float64 }
func (*Square) isShape() {}

type Triangle struct{ Base, Height float64 }
func (*Triangle) isShape() {}
```

The stubs are noise. They belong in a generated file that you never read.

## How it works

You write the interface and variants. The generator writes the method stubs.

**You write** (`shape.go`):

```go
//sumtype:decl
type Shape interface {
    isShape()
}

//gosumtype:impl Shape
type (
    Circle struct {
        Radius float64
    }
    Square struct {
        Side float64
    }
    Triangle struct {
        Base   float64
        Height float64
    }
)
```

**Generator writes** (`shape_sumtypes.go`):

```go
// Code generated by go-sumtype. DO NOT EDIT.

package yourpkg

func (*Circle) isShape()   {}
func (*Square) isShape()   {}
func (*Triangle) isShape() {}
```

Generic variants are handled automatically:

```go
//sumtype:decl
type Shape interface {
    isShape()
}

//gosumtype:impl Shape
type (
    Circle   struct{ Radius float64 }
    Square   struct{ Side float64 }
    Scaled[N interface{ ~float64 }] struct {  // type params stripped in receiver
        Inner  Shape
        Factor N
    }
)
```

Generates:

```go
func (*Circle) isShape()    {}
func (*Square) isShape()    {}
func (*Scaled[N]) isShape() {}
```

## Usage

```sh
go-sumtype <file.go> [...]
```

Output is written to `<file>_sumtypes.go` alongside the input file. If the file contains no `//sumtype:decl` blocks, no output file is created.

### With `go:generate`

Add a directive at the top of the file:

```go
//go:generate go-sumtype $GOFILE
```

Then run:

```sh
go generate ./...
```

## Two-annotation pattern

Two annotations work together — each has a distinct purpose:

| Annotation | Goes on | Read by |
|---|---|---|
| `//sumtype:decl` | Interface declaration | `go-check-sumtype` linter |
| `//gosumtype:impl Name` | Variants `type (...)` block | `go-sumtype` generator |

**`//sumtype:decl` placement** — must be on the `type` declaration itself, not inside a grouped block. The linter reads `GenDecl.Doc` (the doc comment before `type`), not `TypeSpec.Doc` (a comment inside a `type (...)` block).

```go
//sumtype:decl          ← correct: on the type declaration
type Shape interface {
    isShape()
}

type (
    //sumtype:decl      ← wrong: silently ignored by the linter
    Shape interface {
        isShape()
    }
)
```

**`//gosumtype:impl Name` placement** — on the variants `type (...)` block, where `Name` matches the interface declared with `//sumtype:decl`:

```go
//gosumtype:impl Shape
type (
    Circle struct{ Radius float64 }
    Square struct{ Side float64 }
)
```

The interface must be declared in the **same file** as the variants block.

## Rules

- The interface named in `//gosumtype:impl Name` must be declared in the same file.
- The interface must have exactly one unexported, zero-parameter, zero-return marker method (e.g. `isShape()`).
- Multiple sumtypes per file are supported — each variants block has its own `//gosumtype:impl Name`.
- The interface and variants block may appear in any order in the file.

## Marker method naming

The method name is read directly from the interface body. The generator does not derive it from the interface name, so it can be anything — it does not have to follow the `is` + interface name pattern:

```go
//sumtype:decl
type Shape interface {
    isShapeVariant()   // fine — not "isShape"
}

//gosumtype:impl Shape
type (
    Circle struct{ Radius float64 }
    Square struct{ Side float64 }
)
```

The generator reads whichever name you write. The linter enforces exhaustiveness on whichever name implements the interface.

## Linter integration

Install [go-check-sumtype](https://github.com/alecthomas/go-check-sumtype) and run it as a standalone command:

```sh
go install github.com/alecthomas/go-check-sumtype/cmd/go-check-sumtype@latest
go-check-sumtype ./...
```

> **Note:** Do not use the `gochecksumtype` linter via golangci-lint. Due to a [known bug](https://github.com/golangci/golangci-lint/issues/4158), it only checks exhaustiveness within a single package — it silently misses non-exhaustive switches when the sum type is declared in one package and the switch is in another. The standalone binary does not have this limitation.

It will report non-exhaustive type switches over any `//sumtype:decl` interface:

```go
func area(s Shape) float64 {
    switch v := s.(type) {
    case *Circle:
        return math.Pi * v.Radius * v.Radius
    case *Square:
        return v.Side * v.Side
    // missing *Triangle → linter error
    }
}
```

**Generic variants are not checked.** `go-check-sumtype` cannot enumerate all possible type arguments, so generic variants (e.g. `Scaled[N]`) are silently excluded from exhaustiveness checks. Missing a `case *Scaled[float64]:` will not be flagged.
